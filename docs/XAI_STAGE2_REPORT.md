# Shadow Guard 2.0 — XAI Stage 2 Completion Report: Unified Tri-Model Explanation Engine

## 1. Executive Summary

**XAI Stage 2 (Unified Tri-Model Explanation Engine)** integrates the three validated Stage 1 model-specific explainers (`RandomForestSHAPExplainer`, `IsolationForestAnomalyExplainer`, and `AutoencoderReconstructionExplainer` in `shared/ml/xai_explainer.py`) into a single read-only explanation orchestrator (`UnifiedTriModelExplainer` in `shared/ml/unified_xai_engine.py`).

### Key Stage 2 Compliance Guarantees
1. **Zero Modification to Stage 1 Implementation**: `shared/ml/xai_explainer.py` and `ml-detection-service/tests/test_xai_explainer.py` were preserved unchanged (`0` lines modified in Stage 2).
2. **100% Detection Decision & Score Invariance Across All 384 Held-Out Flows**: Evaluating `UnifiedTriModelExplainer` across all `384` held-out test flows (`data/autoencoder_flow_dataset_v2.json` `splits.test_set`) produces **zero mismatches (`0/384`)** against `data/held_out_384_tri_model_predictions.json` across `final_decision`, `is_anomaly`, `fused_anomaly_score`, `recommended_action`, `auto_block_permitted`, `decision_rule`, and individual model scores.
3. **Strict Separation of Mathematical Scales (No Cross-Scale Averaging)**:
   - `RandomForestSHAPExplainer` outputs additive attack-class probability deltas $\phi_j^{(1)}(\mathbf{x}) \in [-1, 1]$ (`SUPERVISED_CLASS_PROBABILITY_SHAP_ADDITIVE_ATTRIBUTION`, `is_exact_shap = True` via `shap.TreeExplainer` v0.54.1).
   - `IsolationForestAnomalyExplainer` outputs reference-population median-replacement raw decision score shifts and robust Z-scores (`UNSUPERVISED_ANOMALY_SCORE_NOT_PROBABILITY`).
   - `AutoencoderReconstructionExplainer` outputs per-feature squared reconstruction errors $(z_j - \hat{z}_j)^2$ vs the frozen validation threshold $P_{97} = 0.503670$ (`RECONSTRUCTION_ERROR_MSE_NOT_PROBABILITY`).
   - `UnifiedTriModelExplainer` **never** averages, sums, or directly equates these three incommensurable quantities.
4. **Collinearity-Aware Shared vs Model-Specific Attribution Analysis**:
   - Because all `69` features in `v2.0-69dim` are deterministic nonlinear projections of only three raw scalars (`packets`, `bytes`, `duration`)—including `13` exact polynomial duplicates (`f_25..f_39`) and `14` rank-1 collinear harmonic padding columns (`f_55..f_68`)—shared and model-specific drivers are computed at:
     1. **Raw Measurement Family Level (`packets`, `bytes`, `duration`)**: Comparing each model's internal attribution share (`share_of_total` within that model's own attribution space).
     2. **Canonical Deduplicated Feature-Concept Level (`_canonical_concept_id`)**: Collapsing exact duplicate groups (`concept_poly_even_packets2_dur2`, `concept_poly_odd_pkt_bytes_dur2`) and collinear padding (`concept_harmonic_collinear_padding`) before checking top-5 concept overlap across models, while explicitly marking `is_collinear_or_duplicate_group: true`.

## 6. Remaining Scientific & Operational Limitations
1. **3-Scalar Intrinsic Dimensionality (`packets, bytes, duration`)**: Because all `69` features are derived from `packets`, `bytes`, and `duration`, explanations cannot inspect application-layer payload syntax or cryptographic indicators directly from the 69-feature vector.
2. **Cross-Label Feature Collisions**: Flows sharing identical `(packets, bytes, duration)` measurements across normal and attack traffic (`flow-collision-norm-00` vs `flow-collision-atk-00`, and `flow-collision-norm-01` vs `flow-collision-atk-01`) receive identical model scores and feature attributions, and are automatically flagged with `is_cross_label_feature_collision = true` and `explanation_reliability_tier = "AMBIGUOUS_3_SCALAR_FEATURE_COLLISION"`.
3. **API & Dashboard Integration Pending**: In accordance with stage-gated execution, REST API endpoints (`/api/v2/xai/*`), PostgreSQL persistence (`004_xai_explanations.sql`), and SOC Dashboard Module 11 UI have not yet been started and are scheduled for **XAI Stage 3** and **XAI Stage 4**.
